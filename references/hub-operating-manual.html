How the Hub Works

Your git-backed second brain — one canonical copy on main, worked from two computers. This is the field guide: the folder map, the daily loop, and how to start anything new.

01

The one rule, and the loop

Everything else hangs off this. Do it every session, on whichever machine you're at.

★

`main` is the single source of truth. Both computers only pull and push main. You never lose work to a credit limit or a second machine — worst case, push what's done, switch, pull, keep going.

START

Pull

Get the latest before you touch anything.

git checkout main
git pull
DO

Work

Edit docs or build the project — one thing at a time.

CAPTURE

Record

Update the projects/ record; log any real decision.

FINISH

Push

Send it up so the other machine sees it.

git add -A
git commit -m "…"
git push
02

Where everything lives

Seven folders, each with one job. Put new material where it belongs and the hub stays findable.

context/
Read first. Who you are, your role, team, goals, and current-priorities.md. The orientation layer that makes any new Claude session instantly useful.
projects/
One file per project. Status, what shipped, how to resume. e.g. fbcgi-staff-hub-reporting.md.
decisions/
Append-only. log.md — every meaningful decision with what & why. Never rewrite past entries.
references/
Reusable knowledge. playbooks/ (methods you follow), sops/ (step-by-step procedures), examples/.
templates/
Doc skeletons. Copy-to-start files like session-summary.md.
archives/
Retired material. Finished or superseded work kept for the record.
PhaseU/
The office-automation build. Large, self-contained M365 project (Power Automate · Planner · SharePoint).
Front door

README.md is the map · SYNC.md is the two-computer process. When in doubt, start there.

03

Starting a new project

A genuine sequence — follow it in order and the project is trackable from day one, on both machines.

  1. Pull, then create the record

    Start from a fresh main. Add one file: projects/<short-name>.md.

    git checkout main && git pull
    # then create projects/<short-name>.md

  2. Write the header block

    Top of the file: Type · Status · Last-updated · Owner, then a one-line "what & why." This is what future-you (or the other computer) reads first.

  3. Capture the essentials

    Where it lives (tools, URLs, IDs), what's been built, the data source, and a "how to resume" section. Enough that any session can pick it up cold.

  4. Log the founding decisions

    Append to decisions/log.md anything you chose and why — data source, phase-1 approach, deferred work.

  5. Add it to priorities, then push

    Put a line in context/current-priorities.md so it surfaces next session. Commit and push to main.

04

Adding content as you go

Small, frequent updates beat big rewrites. Match the material to its folder.

decisions/ A decision

Append one line to log.md. Format: [date] DECISION: … | REASONING: … | CONTEXT: …

Never edit old entries — the value is the unbroken trail.

context/ Orientation

Keep current-priorities.md honest at the start/end of a session. Fill the (fill in) blanks in me.md, team.md, goals.md when you have a minute.

references/ Know-how

A method you follow → playbooks/. A repeatable procedure → sops/. A worked sample → examples/.

templates/ A reusable skeleton

Made a doc you'll want to stamp out again? Save a blank version here and copy it next time.

05

Landing a Claude-on-the-web session

Web sessions push to their own claude/… branch. That's delivery, not storage — land it on main right away.

git checkout main && git pull
git merge origin/claude/<the-branch-name> # clean merge for docs
git push
Why it matters

If finished work stays parked on a feature branch, the other computer's plain git pull won't see it. Merge to main, then start the next task from a fresh pull — don't keep stacking on the old branch.

06

Cheat-sheet

The whole workflow in six lines.

# before every session — on either computer git checkout main && git pull # after every session git add -A && git commit -m "what changed (date)" && git push # land a Claude-web task branch onto main git merge origin/claude/<branch> && git push # see what's changed / which branch you're on git status
